# 업무바통 – 전임자의 경험을 후임자에게, 끊김 없이

> 2026 공공 AI 대전환 챌린지 · 세션2 AI 미션 경진대회 · 지정과제 ① **업무바통(인수인계)**

전임자의 업무 폴더(한글·PDF·엑셀·워드·메일·메모)를 **폴더째** 넣으면,
① 출처가 달린 **인수인계서 초안**을 만들고, ② 문서에 없는 노하우는 **암묵지 인터뷰**로 전임자에게 되묻고,
③ 후임자는 **업무 달력·협업 지도·질문하기·첫 30일 플랜**으로 바로 일을 이어받습니다.

```
 ① 자료 넣기 ──────────▶ ② 전임자 검수 ─────────────▶ ③ 후임자 수령 ───────────▶ 바통 터치
 폴더째 투입              출처 각주 · 신뢰 신호등          업무 달력 · 협업 지도        양측 확인
 원본 읽기 전용            자료 간 불일치 탐지              근거 기반 질의응답           Word/HTML 내보내기
 민감정보 자동 가림         암묵지 인터뷰 → 자동 반영         첫 30일 플랜(D-day)          처리 이력
```

## 바로 실행

| 환경 | 방법 |
|---|---|
| **Windows** | `run.bat` 더블클릭 (`실행.bat`도 같음) |
| macOS / Linux | `./run.sh` (안 되면 `bash run.sh`) |
| 직접 실행 | `python run.py` (부족한 라이브러리는 자동 설치) |

처음 실행하면 아래 과정을 **자동으로** 진행하고, 두 번째부터는 바로 시작합니다.

1. **실제로 동작하는 Python 3.10 이상 찾기** – PATH의 `python` → `py` 런처(3.13~3.10) → 기본 설치 폴더 순으로 찾고, 실행하면 스토어가 열리는 *Microsoft Store 가짜 python.exe*는 시험 실행으로 걸러 냅니다.
2. **전용 실행 환경(`.venv`) 만들기** – PC의 다른 프로그램과 섞이지 않게 폴더 안에 따로 만듭니다. 손상되었거나 파이썬을 바꾼 경우 스스로 다시 만듭니다.
3. **라이브러리 설치** – `requirements.txt`가 바뀌었을 때만 설치(설치 기록 `.venv/requirements.stamp`). `wheels` 폴더가 있으면 인터넷 없이 설치합니다.
4. **실행** – 브라우저가 `http://127.0.0.1:8765`로 열립니다. 포트가 사용 중이면 다음 빈 포트를 씁니다.

| 옵션 | 설명 |
|---|---|
| `run.bat --check` | 파이썬·라이브러리·작업 폴더 점검만 하고 종료 |
| `run.bat --reinstall` | 실행 환경을 지우고 처음부터 다시 설치(문제가 생겼을 때) |
| `run.bat --model ollama-exaone` | 사용할 AI 모델 프로필 지정 |
| `run.bat --port 9000` | 포트 변경 |

- 필요 환경: Windows 10/11 · macOS · Linux, Python 3.10 이상(3.11·3.12·3.13에서 시험), Edge·Chrome·Whale
- 처음 화면에서 **‘✨ 샘플로 체험’**을 누르고 두 가지 모의자료(정보보안 담당 / 시설관리 담당) 중 하나를 고르면 전 과정을 바로 볼 수 있습니다.
- **LLM이 없어도 동작**합니다(규칙엔진 모드). AI 모델을 연결하면 문장 정리, 현안 통합, 인터뷰 질문, 질의응답 품질이 올라갑니다.

### 인터넷이 막힌 PC
1. 인터넷이 되는 Windows PC에서 `오프라인_설치파일_만들기.bat` 실행 → `wheels` 폴더에 64비트 Windows용 설치 파일(Python 3.10~3.13 모두)이 내려받아집니다.
   - macOS/Linux에서 직접 받을 때: `pip download -r requirements.txt -d wheels --only-binary=:all: --platform win_amd64 --python-version 311` (대상 PC의 파이썬 버전에 맞춰 반복)
2. 업무바통 폴더를 **`wheels` 폴더 포함 통째로** 인터넷이 막힌 PC로 옮깁니다.
3. `run.bat` 실행 → “wheels 폴더에서 설치합니다(인터넷 불필요)”가 표시되며 설치됩니다.
- Python 설치 파일(python.org의 Windows installer)도 함께 옮겨 먼저 설치해 두세요.

### 문제 해결
| 증상 | 해결 |
|---|---|
| “Python 3.10 이상을 찾지 못했습니다” | python.org에서 설치, 첫 화면 **“Add python.exe to PATH”** 체크 후 다시 실행 |
| “실행 환경을 만들지 못했습니다” | 바탕화면·문서처럼 쓰기 가능한 폴더에 압축을 풀고 실행(백신 예외 필요할 수 있음) |
| 라이브러리 설치 실패 | 인터넷/프록시 확인, 또는 위 ‘인터넷이 막힌 PC’ 방법 |
| 그 밖의 오류 | `run.bat --reinstall`, 상태 확인은 `run.bat --check` |
| 브라우저가 안 열림 | 검은 창에 표시된 주소(`http://127.0.0.1:8765`)를 직접 입력 |

## 주요 기능

### 지정과제 기본 기능
| 과제 카드 기본 기능 | 업무바통 구현 |
|---|---|
| 한글·PDF·엑셀 등 섞인 자료를 폴더째 넣어도 작동 | HWP(5.x)·HWPX·PDF·XLSX/XLSM/CSV·DOCX·PPTX(발표자 메모 포함)·EML(첨부 포함)·MSG·TXT/MD·이전 바통 파일. 한글·워드 문서 속 **표는 ‘머리글: 값’ 행으로** 읽어 업무분장표·연락처표·계약현황표를 그대로 이해 |
| 자료에 근거한 초안 + 각 내용의 출처 확인 | 모든 문장에 근거 칩 → 클릭하면 **원문 해당 위치(쪽·문단·시트·행·메일)**가 형광펜과 함께 열림 |
| 전임자가 검토·수정 | 문장별 ✔확인 / ✏수정 / 🗑삭제 / 직접 추가, 검수 진행률, 수정 이력 |

### 선택 기능(과제 카드 예시) – 모두 구현
- **연간 업무 달력**: 매월·매분기·매년 반복 업무와 기한을 12개월 달력으로(기한·반복 색 구분)
- **R&R·연락망·현안 정리**: 담당 업무 개요, 협의할 사람(메일 송수신 빈도로 중요도), 진행 중 현안(**상태·기한·다음 할 일**을 따로 뽑아 D-day 순 정렬). 계약현황표의 ‘진행 중’ 행, 받은 요청 메일(“~까지 제출 바랍니다”), 보낸 메일의 회신 대기, 공문의 조치 요구까지 현안 후보로 잡음
- **달력의 시점 표시**: 기준일보다 지난 일은 흐리게, ‘완료·기한 지남·후속 조치 확인’ 표시
- **공식 문서와 개인 메모 구분 + 누락·충돌·불확실 표시**: 신뢰 신호등(공식/메일/메모/구술/근거없음)과 ‘확인이 필요한 사항’ 자동 정리
  - 자료 간 날짜 충돌(예: 착공일 메모 10/27 ↔ 업체 메일 11/3), 기준일 기준 **기한 지남**(예: 10/6 예정 검사), **연락처 변경 메모**, “아마·~로 알고 있음·미정” 같은 **불확실 표현**, 결론 없는 협의, 메모에만 있는 내용
  - **누락 점검**: 연락처가 없는 사람, 기한이 안 적힌 현안, 일정이 하나도 없는 달, 담당 업무·연락처가 비어 있는 경우
  - 전용 **③ 확인 필요** 화면에서 종류별·중요도(상·중·하)로 보고, 처리 내용을 적어 ‘처리 완료’(되돌리기 가능) → 인수인계서에 ‘전임자 확인’으로 남음
- **후임자 질문에 답변**: 자료 + 전임자 인터뷰 답변만 근거로 답하고 근거 표시. “이번 달 기한?”·“11월에 할 일?”은 달력에서, “정민재 연락처?”·“냉난방기 공사 누구랑 협의해?”는 연락망에서, **“급한 현안 알려줘”**는 기한 지남·불일치·D-30 이내 현안을 D-day 순으로 바로 답함(바뀐 번호 경고 포함)
- **후임자 맞춤 업무매뉴얼**: 화면의 첫 30일 플랜(D-day 타임라인, 첫 주 체크리스트) + **업무매뉴얼 문서**를 **착임일·경력(처음 맡음 / 유사 업무 경험)에 맞춰** 한글(.hwpx)·워드·마크다운으로. 착임월부터 12개월 일정, 기한 순 현안(남은 기간), 꼭 알아둘 연락처 표, 노하우, 아직 확인할 것을 담고, 처음 맡는 사람에게만 용어 풀이를 넣음
- **문서시스템 API 연계**: 처음 화면 ‘문서시스템 연계’에서 문서시스템 주소와 전임자 이름을 넣으면 API로 목록·본문을 받아 바로 분석합니다. 함께 든 **모의 문서시스템 API**(`/mock-docsystem/documents?owner=`, `/mock-docsystem/documents/{id}/content`)로 시연하며, 실제 구축 시 주소만 바꾸면 됨
- **자료 내용 보기**: ① 자료 화면에서 파일별로 분석에 쓴 텍스트(민감정보 가림 후)와 원본 지문을 바로 확인

### 업무바통만의 차별점
0. **🧪 인수 리허설** – 확정된(전임자가 확인·수정한) 인수인계 내용으로 기한·담당자·현안 상태·자료 위치·노하우 문제를 10개씩 자동으로 내고, 후임자의 **인수 준비도(%)**를 잽니다. 정답은 서버에서만 채점하고, 틀린 문제는 근거 원문으로 바로 이어집니다. 못 맞힌 항목부터 다시 나오며, 전임자가 항목을 고치면 그 항목은 다시 확인해야 준비도에 들어갑니다. 답이 둘일 수 있는 문제(같은 문장의 서로 다른 날짜, 뜻이 비슷한 상태 보기 등)는 내지 않습니다.
0. **🧬 지식 릴레이(.baton)** – 검수된 내용과 인터뷰 답변을 바통 파일로 저장해 두면, 다음 인수인계 때 자료 폴더에 넣기만 해도 근거로 이어지고 담당자 계보(1대 → 2대 → 3대)가 쌓입니다. 사람은 바뀌어도 업무 지식은 남습니다.
0. **🎭 AI 전임자 분신** – 후임자는 ‘AI 김바통’에게 묻고, 자료에 없으면 “진짜 김바통 님께 물어봐야 해요”라며 질문을 넘깁니다(실제 본인이 아님을 화면에 표시).
0. **📅 내 일정으로 내보내기(.ics)** – 업무 달력을 Outlook·그룹웨어·휴대폰 달력에 매월·매년 반복 일정 + 기한 3일 전 알림으로 등록합니다.
1. **암묵지 인터뷰** – 문서에 결론이 없거나, 자료끼리 날짜가 다르거나, 메모에만 있는 내용을 찾아 *전임자에게 질문*합니다. 답변은 ‘전임자 구술’ 근거로 인수인계서에 자동 반영됩니다. (인수인계서에 노하우가 안 담기는 근본 원인 해결)
2. **질문 바구니** – 후임자가 자료로 답을 못 찾은 질문은 버튼 하나로 전임자 인터뷰 목록에 쌓입니다(인사이동 후에도 이어지는 인수인계).
3. **신뢰 신호등** – 공식문서 / 메일 / 개인메모 / 전임자 구술 / 근거없음을 색으로 구분. LLM이 출처 없이 만든 문장은 빨간색으로 표시하고 전임자가 확인해야만 인수인계서에 포함(환각 차단).
4. **협업 지도** – 메일 주고받은 횟수·문서 언급으로 ‘누구와 어떤 일로’ 협의하는지 한눈에.
5. **바통 터치** – 전임자 확인 → 후임자 수령의 양측 확인, 원본 무결성(SHA-256) 재확인, 처리 이력. 인수인계서를 **한글(.hwpx)**·워드·인쇄용 HTML·마크다운으로 내보내기(일정·현안·연락망은 표, 모든 줄에 근거 번호 + 근거 목록).
6. **보안 기본값** – 원본 읽기 전용(처리 전후 해시 비교로 증명), 비밀번호·주민번호·휴대전화·계좌번호 자동 가림(LLM에도 가린 텍스트만 전달), 기본 접속 범위 127.0.0.1, 외부 CDN 없음(폐쇄망 동작).

## AI 모델(LLM) 연결 – 특정 모델에 종속되지 않음

`설정 → AI 모델`에서 고르거나 `python run.py --model ollama-exaone`처럼 실행합니다.
OpenAI 호환 Chat Completions API를 쓰는 모든 모델을 연결할 수 있으며, `config/settings.json`에 기본 프로필이 들어 있습니다.

| 프로필 | 모델 | 연결 |
|---|---|---|
| `offline` | 없음(규칙엔진) | 설치 불필요 – 기본값 |
| `ollama-gemma` / `ollama-exaone` / `ollama-llama` | Gemma 3 / EXAONE 3.5 / Llama 3.1 | Ollama(`http://localhost:11434/v1`) |
| `vllm-gpt-oss` | GPT-OSS 20B | vLLM 등 OpenAI 호환 서버 |
| `hyperclova-x` | HyperCLOVA X (HCX-005) | CLOVA Studio OpenAI 호환 API, 키: `CLOVA_STUDIO_API_KEY` |
| `solar` | Solar Pro 2 | Upstage API, 키: `UPSTAGE_API_KEY` |

- 연결 방식: **OpenAI 호환**(AI 공통기반·vLLM·Ollama `/v1`·LM Studio 등) 또는 **Ollama 기본 API**(`/api/chat`). 설정 화면의 **‘목록’** 버튼으로 서버에 실제 등록된 모델 이름을 불러와 고릅니다.
- **모델 계열별 차이 자동 처리**(앱 코드 수정 없음)

  | 계열 | 처리 |
  |---|---|
  | 젬마(Gemma) | system 역할을 거부하는 서버면 지시문을 첫 질문에 합쳐 다시 요청 |
  | GPT-OSS·Qwen(추론형) | 토큰 여유를 늘리고, 생각만 하다 빈 답이면 한도를 키워 다시 요청 |
  | 엑사원(EXAONE)·하이퍼클로바X 등 | 답 앞의 생각 과정(`<think>`, `<thought>`, 닫히지 않은 것 포함) 제거 |
  | 공통 | 코드블록·끝 쉼표·잘린 JSON 복구, 근거 ID를 원문과 대조해 없는 근거는 ‘근거 없음’ 처리 |

- **모델 자가진단**(화면): 설정의 ‘전체 모델 자가진단’이 ①한국어 응답 ②JSON 구조화 출력 ③출처 인용 준수를 시험해 표로 보여 줍니다.
- **모델 2종 검증 보고서**(제출용): Windows는 [Ollama](https://ollama.com/download) 설치 후 `모델검증.bat` 더블클릭 → 젬마·엑사원을 내려받아 같은 기능을 돌리고 결과를 **원문 정답과 대조**해 `verify_report.md`를 만듭니다. 다른 모델: `모델검증.bat llama3.1:8b gpt-oss:20b`
  - 직접 실행: `python tools/verify_models.py --base-url http://localhost:11434/v1 --models gemma3:4b exaone3.5:7.8b`
  - ‘통과’ 기준: 초안을 모델이 작성하고 경고가 없음 / 질문 답의 날짜·전화번호가 원문에 실제로 있음 / 자료에 없는 질문엔 ‘찾을 수 없음’
  - `--mock`: 가짜 모델 서버로 연결 경로와 계열별 차이 처리만 시험(실제 성능 검증 아님). 현재 개발 환경에서는 이것만 확인했습니다.
- 프롬프트는 `config/prompts/*.txt` 텍스트 파일이라 기관이 직접 다듬을 수 있습니다.
- LLM 응답이 깨지거나 연결이 끊기면 해당 항목만 규칙엔진 결과로 자동 대체합니다.

## 기관별 설정
- `config/template.json` (화면: 설정 → 인수인계서 양식): 항목 이름·순서·사용 여부, **키워드 기반 기관 고유 항목** 추가
- `config/settings.json`: 기관명·부서, 모델 프로필 / API 키는 `config/settings.local.json`(저장소 제외)에 따로 저장


## 알려진 제약
- 스캔 PDF(이미지)는 OCR이 없어 읽지 못합니다(화면에 ‘텍스트 없는 PDF’로 표시).
- 암호가 걸린 HWP·배포용 문서는 미리보기 텍스트만 읽습니다.
- 구형 엑셀(.xls)·한글 97 문서는 지원하지 않습니다(새 형식으로 저장 후 투입).
- 규칙엔진의 날짜·사람 인식은 한국 공문서 표기 위주이며, 결과는 전임자 검수를 전제로 합니다.
